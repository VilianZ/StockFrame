# StockFrame frontend critique

## Overall impression

StockFrame sudah memiliki identitas visual yang kuat dan product-specific. Alur Persuade ke Operate terbaca jelas: landing memperkenalkan cara kerja berbasis bukti lalu menyerahkan pengguna ke meja riset yang fokus. Nilai heuristik keseluruhan 26/40. Fondasinya baik, tetapi belum siap dianggap selesai karena masalah keterbacaan mobile, metafora grafik hero, recovery state F2, disclosure angka ilustratif, dan bukti interaction testing.

## Design specificity

Desain terasa authored dan tidak mudah dipindahkan ke SaaS generik: black frame, lime signal, artefak evidence, dan Data ke Engine ke Interpretasi membangun identitas StockFrame. Namun signal line hero terbaca sebagai grafik harga bullish sehingga bertentangan dengan pesan bahwa produk bukan alat prediksi harga dan dengan aturan lime sebagai provenance, bukan sentimen.

## Strengths

- Transisi Persuade ke Operate berhasil; form tidak merusak hero.
- Provenance menjadi bagian dari desain, bukan disclaimer tambahan.
- F2 memiliki controlled fields, validasi lokal, aria-live, AbortController, typed response parsing, ambiguity state, dan success handoff.
- Empty validation terkonfirmasi di browser tanpa network call.
- Detector statis tidak menemukan pelanggaran otomatis.

## Priority issues

### P1 - Hero mobile terpotong

Pada 390x844, H1, lead paragraph, evidence artifact, dan signal SVG melewati viewport lalu disembunyikan oleh overflow. Ini mengganggu proposisi utama, bukan sekadar polish.

### P1 - Signal line bermakna seperti grafik saham bullish

Polyline menanjak, grid harga, glow, dan aria-label perubahan harga penutupan mengasosiasikan lime dengan performa positif. Ganti menjadi alur evidence Data ke Engine ke Interpretasi atau visual signal non-directional.

### P1 - Recovery error F2 tidak sesuai penyebab

Semua error non-retryable diarahkan ke Perbaiki input, termasuk kegagalan provider atau internal yang bukan kesalahan pengguna. Recovery action harus mengikuti error family.

### P2 - Ambiguity tidak memiliki jalur kembali eksplisit

Candidate selection dan canonical resubmission sudah ada, tetapi aksi Ubah pencarian atau Kembali belum tersedia.

### P2 - Angka demo tampak seperti data live

AAPL, rasio, tanggal efektif, dan confidence perlu label Contoh ilustratif untuk menjaga kepercayaan dan provenance.

### P1 - Acceptance F2 belum dibuktikan lengkap

Implementasi sebagian besar ada, tetapi belum ada component atau E2E regression untuk duplicate submit, cancellation, preserved values, candidate resubmission, loading announcement, retry visibility, dan rendered error recovery. Checklist F2 terlalu optimistis jika semua item ini sudah dicentang.

## F2 verdict

F2 secara arsitektur sebagian besar terpenuhi. Success state yang hanya menyimpan typed response dan menyerahkannya ke F3 adalah benar; full report renderer bukan tanggung jawab F2. Status yang tepat saat ini adalah partially accepted: dua gap semantik masih ada dan interaction regressions wajib belum tersedia.

## Persona red flags

- Pemula dapat bingung oleh canonical, formula ID, evidence ID, dan confidence model.
- Pengguna mobile kehilangan sebagian headline dan pengantar.
- Pengguna yang menghadapi kegagalan provider dapat disalahkan melalui CTA Perbaiki input.
- Pengguna finansial dapat mengira angka ilustratif sebagai data aktual.

## Minor observations

- Header CTA 38 px dan secondary text link 26 px berada di bawah target sentuh 44 px.
- Metadata mono dan disclaimer terasa terlalu kecil.
- Focus order terlihat benar dari source, tetapi runtime Tab verification tidak konklusif.
- Loading, ambiguity, error API, cancellation, dan success tidak dipicu secara live agar tidak memanggil provider.
